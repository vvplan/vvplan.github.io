# XEdu Client 官网展示设计

## 目标

让访问虚谷计划官网的教师和学生在首页快速发现 XEdu Client，并在独立项目页理解它解决什么课堂问题、能完成哪些实验、如何获取体验版和源码。

XEdu Client 的统一定位为：**面向 AI 教学场景的桌面实验工作台**。项目页不把它描述为管理后台、单一 Jupyter 启动器或可在浏览器直接运行的网页应用。

## 已选方案

采用“首页重点聚焦区 + 独立项目页 + 外部资源分流”的结构。

- 首页在“八大核心项目”标题与横向卡片之间加入一块横跨内容区的 XEdu Client 聚焦模块。它承担项目识别、核心定位和进入详情页三个任务。
- 新增 `xedu-client.html`，作为产品说明页，展示真实界面、四项核心能力、教师与学生的典型路径，以及体验版、源码和使用文档入口。
- 软件包继续由 `haitao926/xedu-client` 的 GitHub Release 托管；源码以 `XEduPro/xedu-client` 为准；文档链接指向源码仓库中的教师文档。官网只负责展示和导流。

### 未采用的方案

1. 只在横向项目列表中新增第九张卡片。改动小，但不能形成视觉重点，也无法解释桌面客户端与 XEduPro 的关系。
2. 把 XEdu Client 放到首页首屏，替换虚谷计划总品牌叙事。曝光最高，但会让组织官网变成单产品官网，削弱现有八大项目的整体关系。
3. 把桌面应用前端构建产物部署到 GitHub Pages。该应用依赖 Electron、Flask、本地 Python 和 `/api/*`，静态托管无法提供完整功能。

## 信息架构

### 首页聚焦区

内容顺序：

1. “2026 重点项目”状态标识
2. 项目名 `XEdu Client`
3. 一句话定位“面向 AI 教学场景的桌面实验工作台”
4. 四个能力关键词：课程资源、Jupyter、Scratch、课堂接入
5. 主按钮“了解项目”，进入 `xedu-client.html`
6. 次按钮“查看源码”，打开 `https://github.com/XEduPro/xedu-client`
7. 真实界面截图，帮助教师快速判断产品形态

聚焦区位于“八大核心项目”区内、普通项目卡片之前。它属于项目生态，但在视觉层级上高于普通卡片。

### 独立项目页

1. 首屏：项目名、定位、体验版与源码按钮、真实产品界面。
2. 核心能力：课程资源、Jupyter/Python、Scratch、课堂接入，每项用一句用户结果描述，不罗列 API。
3. 课堂路径：并列呈现教师和学生两条流程。
4. 产品关系：说明 XEduPro 提供 AI 学习工具，XEdu Client 把课程、实验环境和课堂分发组织到同一桌面工作台。
5. 获取入口：`V2.0` 目前是预发布版本，按钮明确标记“下载体验版”；同时提供源码和教师文档。

## 视觉与交互

- 保留现有官网的蓝、青、白主色和 Noto Sans SC 字体，新增少量绿色用于课堂与运行状态，不重做全站品牌。
- 首页重点区使用左右布局：左侧信息，右侧真实界面；移动端改为上下布局，按钮可换行，截图保持固定宽高比。
- 详情页首屏沿用内页固定白色导航，但使用更高的信息密度和真实界面作为第一视口信号。
- 卡片圆角不超过现有站点规范；重点模块不嵌套装饰卡片。
- 使用轻量进入动画，并尊重 `prefers-reduced-motion`。
- 所有外部链接使用 `target="_blank" rel="noopener"`，所有图片包含能说明内容的 `alt` 文本。

## 内容边界

- 不承诺当前仓库尚未发布的正式版、自动更新或跨平台完整支持。
- `V2.0` 预发布页当前包含 Windows `.exe` 与 macOS Apple Silicon `.zip`，统一先进入 Release 说明页，由用户选择系统。
- 不在官网重复维护安装细节；安装说明继续以源码仓库 `docs/teacher/INSTALL.md` 为准。
- 不修改原有“八大核心项目”数量和既有 XEduPro 卡片，避免未经项目组确认改变组织项目口径。

## 文件边界

- 修改 `index.html`：加入重点项目模块。
- 新增 `xedu-client.html`：项目详情页。
- 修改 `css/style.css`：加入首页聚焦区与详情页响应式样式。
- 新增 `images/xedu-client/`：产品截图及必要图像资源。
- 不新增 JavaScript 依赖，不增加构建步骤。

## 验证

1. 使用本地静态服务器访问首页和详情页，确认无 HTML 加载错误与资源 404。
2. 在桌面与移动端视口检查首页重点区、详情页首屏、按钮换行和图片裁切。
3. 检查站内链接和三个外部入口：体验版、源码、教师文档。
4. 检查键盘焦点、图片替代文本、移动菜单和 `prefers-reduced-motion`。
5. 对视觉结果执行截图审查；未达到可发布标准则继续调整。
